# mq-sakura-anim

给 [SakuraQR](https://github.com/KiriKira/SakuraQR) 导出的方块樱花树（`.glb`）配的一段小动画。樱花花瓣从树冠里飘下来，三个方块小人在树下绕着树干你追我赶。动画会配合背景音乐 muque「いいんじゃない」演出：一头巨大的鲸鱼从高空游下来，绕着树冠游动，三人停下来看，然后鲸鱼游走，三人继续往前蹦蹦跳跳。动画写成一个 ES 模块 `scene.js`，可以放进别人的网页里跑，也可以用在 AR 里。

- `index.html`：网页本身，也是自检页。打开是 3D 动画，左上角的按钮切换到 AR（用手机相机看打印出来的树），再按一次切回来；带 `?rec=1` 时底部多一个录像按钮
- `ar.html`：旧链接，跳转到 `index.html?ar=1`
- `walkers.html`：三个小人的模型图（正面、四分之三侧、侧面、背面），`?clip=run|look|hop` 切换动作
- `whale.html`：鲸鱼的模型图

## 接口

```js
import setup from './scene.js';
const { update, dispose } = await setup({ THREE, stage, tree, info, mode, showLength });
// 每帧调用 update(dt, elapsed, showTime)，单位秒；用完调用 dispose()
```

- `stage` 是一个 `THREE.Group`，场景里的东西都加在它下面。
- `tree` 是已经放进 stage 的树，只读，不会去动它。
- `info` 就是 `tree.userData.sakuraqr`。
- `mode` 传 `'3d'` 或 `'ar'`，两种模式下场景完全一样。
- 渲染器、相机、相机控制、灯光、背景、地面都由宿主页面负责。scene.js 不碰 DOM，除了 `./assets/`（相对 scene.js 本身）不访问网络。
- `showTime` 是歌曲当前播放到的位置（比如 `audio.currentTime`），演出跟着它走，所以暂停、拖动进度、循环都能对上。不传时，演出用自己的时钟，每 `showLength` 秒（默认 93.27，正好是这首歌的长度）循环一次。
- three.js 用 0.170.0，宿主页面的 import map 要提供 `three` 和 `three/addons/`。

## 场景

- **不放进树里。** 启动时把树自己的三角形按每格 4×4 的分辨率栅格化成竖直的“柱”，每根柱记下哪几段高度是实心的。花瓣和小人只会移动到这些柱显示为空的地方，所以别的码长出来的树也能直接用。
- **花瓣。** 240 片，两种粉色，用一个 InstancedMesh 画。花瓣从树冠外侧的侧壁和树冠下沿冒出来，而且只选下方有足够落差的位置：侧壁旁至少 3 格，树冠下沿则要能一直落到底座。花瓣从不出现在树冠上方，一边长出来一边就开始往下飘，被风吹着边转边落。只有正中间下面有东西时才会停下，碰到台阶边缘会滑下去，所以不会停在半空。落点大多是底座，少数落在较低的树冠台阶上。停几秒后缩小消失（材质只用不透明的，所以用缩小代替淡出），再从树冠里重新出现。小人跑过时会把地上的花瓣踢起来。
- **小人。** `assets/walker-{blue,red,gold}.glb`，配色照参考像素小人：蓝色兜帽配两条辫子、红色法师帽、带角的金色头盔。每个小人是一个蒙皮网格，带一段 `run` 循环动画：身体前倾，并随摆臂左右扭转；手臂和腿大幅摆动；身体在双脚离地时最高、腿经过身下时最低。每一帧都整体抬高到最低点刚好贴地。蓝色小人的两条辫子是单独的关节：平时下垂，每次身体起伏后慢半拍甩起来，跑动时往后飘。
  - 小人沿一个以树干为圆心的圆跑，半径是树干到最近底座边缘距离的一半。只有遇到低矮的树枝和树根时才会偏离圆形绕过去。转弯时身体向内侧倾斜。
  - 蓝色领跑，红色和金色紧跟在后面，彼此忽近忽远。
  - 模型由 `npm run walkers`（`tools/make-walkers.mjs`）生成。精度是每格 8 个体素，同色的面会合并成大矩形，所以三角形不多。单位是“格”（1 = `info.cell`）。
- 随机数用固定种子，每次打开都一样。只用不透明材质，不加灯也不做后处理。对示例树，场景自身一共 4 次绘制调用，约 5 千个三角形。

## 演出（按歌曲时间）

| 时间 | 演出 |
|---|---|
| 0 – 17 秒 | 三人绕着树干追着跑 |
| 17 – 20 秒 | 鲸鱼从高空俯冲下来，到 20 秒刚好进入绕树冠的圆圈 |
| 约 19.6 – 29 秒 | 三人依次减速、停下，转身看鲸鱼：蓝色举手指着，红色双手合在胸前，金色举起双手欢呼 |
| 约 29 秒 | 看腻了，蓝色先跑起来，另外两个跟上；鲸鱼继续绕圈 |
| 55.5 – 63 秒 | 鲸鱼一边绕圈一边抬头往上游，63 秒时完全消失 |
| 63 秒 – 曲终 | 三人改成蹦蹦跳跳地前进（左右手脚交替），直到歌曲循环 |

- **鲸鱼**（`assets/whale.glb`，`tools/make-whale.mjs` 生成）：每格 2 个体素，约 25 格长，带一段 2.4 秒的 `swim` 循环。动画是上下摆尾，鳍跟着拍，头微微点；脊椎分成几节，节与节之间的顶点按两边关节各占一半来混合，弯起来没有裂缝。
- 鲸鱼绕树干游，圆的半径是底座半宽的 2 倍（约 31 格），一圈 40 秒，方向和小人相反。游动时身体向内侧倾斜，脊椎往圆心方向弯，贴着圆弧走。整头鲸鱼一直在树冠上方。场景里只有鲸鱼可以超出“底座外 3 格”的范围，但不会超出它自己的圆（加上鳍）。
- 俯冲和上升时，头朝下或朝上最多 40°，并且会按俯仰角度额外抬高，尾巴和头不会碰到树冠。最后 1.4 秒在高空缩小消失。

- **鲸鱼到达的位置**按三人停下的地方来定：以树干为中心、从上往下看，在三人顺时针 25° 的方向。这样他们是隔着天空看到鲸鱼，不会被树挡住。三人停在哪里取决于追逐的过程，所以俯冲期间（鲸鱼还在高空、看不见时）会预测他们的落脚点，逐渐把鲸鱼在圆上的位置调过去，等三人停稳后锁定。
- 俯冲和上升对称：一开始陡，最后渐渐放平进入圆圈。头的俯仰按前后各 0.5 秒的平均运动方向计算，并做软限制（约 45°），所以从俯冲转成平游是逐渐完成的，不会一下子拉平。

**AR 里的站位**（`setViewer`）：AR 里镜头就是手机，不能像 3D 那样飞过去，所以反过来让小人来找镜头。跟上树以后，AR 页面每帧把手机的位置告诉 `scene.js`（`anim.setViewer(点)`，舞台坐标），三人停下看鲸鱼（约 19.6 秒）之前最多 15 秒，领头的蓝色小人会调整跑速（每秒 1.4–4.2 格，平时本来就在 1.8–3.8 之间变化），让三人正好停在“3D 自动运镜”的那个相对角度：从上往下看，在手机顺时针 45° 的位置，也就是手机相当于在三人逆时针 45° 那一侧，跟 3D 镜头一样。如果那里会被树冠挡住（按树的碰撞柱从三人的腰、头往手机连线检查），或者剩下的时间用自然的跑速赶不到，就选最近的可行位置（最多偏 70°）。站位每 0.2 秒重新选一次，手机移动也跟得上。鲸鱼到达的位置也会考虑手机：手机离得近，鲸鱼绕圈的高度正好在手机看小人的视线上，按 3D 的安排它会从小人前面游过；所以有手机时，鲸鱼到达点在三人顺时针 −40° 到 120° 之间选，要求三人看鲸鱼期间它尽量不挡在手机和三人之间，同时三人还能越过树冠看到它。

帧率低时（比如 4K 下手机只有 10 帧左右），以前每帧的时间步长被限制在 0.1 秒，小人跑得比歌慢，赶不到预定位置；现在有歌曲时间时，小人按实际过去的歌曲时间移动（每帧最多 0.5 秒）。

自测（`test/steer.html`，在 `node test/shots.mjs` 里跑）：手机在 8 个方向、分别在 5、10、15 秒出现（15 秒时离停下只剩 4.6 秒），与不调整对比：停的位置离理想位置的中位数 94° → 11°；24 秒时树挡住某个小人 16/24 → 2/24；看鲸鱼期间鲸鱼挡在前面的时间平均 15% → 20%（只调站位、不调鲸鱼时是 63%）；三人看鲸鱼被树冠挡住 4/24 → 3/24。在软件渲染下用假摄像头跑整页（10 帧/秒，第 8 秒左右认出树）：三人停在离理想位置约 15° 的地方。

**自动运镜**（演示页）：三人停下来看鲸鱼时，镜头在 2.5 秒内滑到以树干为中心、三人逆时针 45° 的一侧（从上往下看），从斜上方往下看，并且拉到足够远，能把三人和鲸鱼一起框进画面；看鲸鱼期间，镜头会缓缓跟着绕圈的鲸鱼走；他们重新跑起来后，镜头再滑回原来的位置。如果树冠会挡住其中任何一个人，镜头会逐步升高，直到三人都看得见。拖动视角会取消这一次运镜。带 `?view=` 或 `?test=` 时不运镜。

## 本地运行和自检

```sh
npm install                 # three@0.170.0，演示页的 import map 指向 node_modules
node test/serve.mjs         # 打开 http://127.0.0.1:8000/（带 Range 支持，音乐才能拖动进度和循环；python3 -m http.server 不行）
node test/shots.mjs         # 无头 Chromium 跑自检，截图到 screenshots/
```

演示页参数：

- `?view=ne|nw|se|sw|top|wide|w0|w1|w2|group`：机位。默认是 `wide`，拉远以便看到鲸鱼；竖屏时会拉近一些、对准得稍低。后几个是对准小人的特写
- `?t=秒`：从歌曲的这个时间开始（先按固定步长快进）
- `?pause=1`：快进后停住
- `?mode=ar`：传给 `setup()` 的 `mode`
- `?nomusic=1`：不放背景音乐，演出用 scene.js 自己的时钟
- `?tree=路径`：换一棵树

`?test=1` 会让动画按固定步长快进 90 秒，每 3 秒检查一次：

- 每个小人的每个顶点（蒙皮之后）和每片花瓣的每个角，用向上的射线数穿过树的次数来判断是否在树里面。这个判断不依赖 scene.js 自己的碰撞柱。
- 有没有东西超出底座 3 格，或者低于 y = 0。
- 小人有没有走出底座，彼此有没有撞上。
- 有没有花瓣飘在附近树冠顶面的上方。
- 每片停住的花瓣（平躺且不动），正中间往下 0.1 格内必须碰到树或底座。
- 演出时间线：鲸鱼只在 17–63 秒出现，而且不超出它自己的圆；看鲸鱼期间，每个人头部到鲸鱼的视线不能穿过树；21.5–28.5 秒三人都停住在看；19.4 秒前和 30–63 秒在跑；64 秒后在跳。鲸鱼的每个顶点（蒙皮之后）也要不在树里、不超出底座 3 格。
- 绘制调用、三角形数和 `update()` 的耗时。
- `dispose()` 之后 stage 里是不是只剩下树。

控制台出现报错或警告、或者访问了本地服务以外的网址，也算失败。`node test/field-debug.mjs` 会用文字打印碰撞柱和环路的长度。

## 背景音乐

演示页循环播放 `audio/bgm.m4a`（AAC，93.3 秒，1.5 MB），右上角的按钮显示正在播放「muque - いいんじゃない」，点击暂停或继续。浏览器不允许没有交互就自动出声，所以自动播放被拒绝时，按钮停在暂停状态，等观众点一下。在歌曲开始之前，演出按 scene.js 自己的时钟走；开始之后跟着歌曲的播放位置走；暂停时故事停在当前位置。按钮一打开页面就显示（暂停状态），不等音频加载完：iOS Safari 在观众点击之前不会加载任何音频，如果等加载完再显示，按钮就永远出不来。音乐文件无法播放时，按钮仍然显示，但变成灰色、不能点击。在歌曲开始之前，按钮旁边会画出一个粉色的手绘箭头，绕一个圈指向按钮。第一次点击按钮（或者自动播放成功）后，箭头消失，之后即使暂停也不会再出现。

## AR

网页左上角的按钮（或者 `?ar=1` 直接进入）：用手机后置摄像头对准打印出来的树，动画就叠在真树上。再按一次回到 3D 动画，相机随之关闭。AR 用到的东西（`ar/mode.js`、识别运行库、约 5 MB 的网络）第一次切换时才加载，只看 3D 动画的人不用下载。两种模式共用同一个渲染器和同一首歌，切换时演出接着当前的歌曲位置继续。打不开相机或加载失败时，自动回到 3D，并在底部提示原因。

- **相机画质**：AR 模式下左上角“3D”旁边的“画质”按钮，点一下换一档：720p → 1080p → 4K → 720p，默认 1080p，选过的会记在这台设备上（`?cam=720|1080|2160` 也可以指定）。按钮上显示相机实际给出的分辨率，相机给不到所选的那一档时会提示。画质越高，手机屏幕上的相机画面越清楚（720p 在手机屏幕上要放大约 2 倍），录像里的相机画面也越清楚；代价是识别运行库每帧要上传更大的图像，帧率可能下降，手机发烫时可以调低。识别网络和二次校正都在固定大小的裁切图上工作，所以分辨率不影响它们的准度：二次校正的误差按实际测量用的裁切像素来判断（之前按相机像素判断，分辨率越高越容易被误判为不合格）。切换时先暂停识别，换好画面后通知运行库新尺寸（`set_source` 加 `set_videoCrop`，只调 `set_source` 识别会失效）并重置跟踪状态。

- [WebAR.rocks.object](https://github.com/WebAR-rocks/WebAR.rocks.object)（`ar/lib/`，MIT）用训练好的网络（`ar/nn/NN_SAKURA.json`，见下面的“AR 训练”）在每一帧里找出树，`ar/pose.js` 把结果换算成树在相机坐标里的位置和朝向。加载网络时要用 WebAR.rocks.train 网页模板的那组参数（`notHereFactor: 0`、每个标签的 `thresholdDetect: 1.0`），不然几乎认不出来。
- 二次校正（`ar/refine.js`）：网络给的位置和朝向只准到 2 mm、2° 左右。底座顶面的深浅码点位置精确已知，边缘清楚，所以沿深浅码点的分界和底座外沿取几百个点，按当前位置投影到画面上，沿边缘的法向在附近找真实的边缘（深浅方向要对），再解出让这些点落到真实边缘上的位置、朝向修正量（最小二乘，Tukey 权重，三轮逐步缩小搜索范围）。被树冠挡住、太斜的点不用。用上的边缘不少于 50 段、平均误差小于 1.5 像素、改动在 8 mm、8° 以内才采用，否则用网络的结果；上一帧校正成功、网络又和它差不多时，从上一帧的结果接着校正，网络短暂丢失时也能单靠校正跟 1 秒。在 16 个已知位置的渲染画面上，位置误差中位数从 1.75 mm 降到 0.5 mm（最大 4.8 → 2.5），朝向从 2.2° 降到 0.8°（最大 5.7° → 1.9°）。`?refine=0` 关掉它做对比。（底座码点的深浅要在把树换成只写深度的材质之前读出来；之前的版本读晚了，只用上了底座外沿，换成完整的码点后，假摄像头视频里校正被采用的帧从约 70% 升到 87%–98%。）
- 打印件是设计树按水平 × 0.8775、高度 × 0.8177 缩放出来的，所以设计树（`tree.glb`）和 `scene.js` 放进同一个按这个比例缩放的组，对齐到识别出的树上，`scene.js` 一行不改（`mode: 'ar'`）。
- 设计树只写深度、不画颜色，真树就能挡住跑到后面的小人和鲸鱼；另一份树和一块桌面只接收阴影，小人和鲸鱼的影子落在真树和桌面上。设计树自己不投影：真树本来就有影子。
- 光从哪来，看真树的影子（`ar/light.js`）：按树的形状预先算好光从 168 个方向（每 15° 一个方位，仰角 20°–80°）照过来时，哪些点在树的影子里：底座周围 6 cm 内的桌面，以及底座上浅色的码点。跟上树以后每 0.3 秒看一次摄像头画面，给每个方向打分：
  - 桌面上“该在影子里的点”比其余的点暗多少，先减掉桌面整体的明暗渐变（按亮度拟合一个平面再减掉），所以“靠近镜头的桌面整体偏暗”不算影子；
  - 同时紧贴着树的地方也要暗：底座外 1.5 cm 内的一圈桌面，或者底座上的浅色码点。树的影子一定从树脚下开始。逆着光拍时，拍摄者自己（手和手机）的影子正好落在“光从对面来”时树影该在的位置，离树又有一段距离，这一条就是用来排除它的；
  - 每个方向取这两项中较小的一个，并在时间上累积（每帧只占 15%），至少被判断过 6 次（约 2 秒）的方向才可以当选，所以个别看错的画面不会把虚拟太阳带偏。分数超过 0.08 才算“硬光”，这时虚拟太阳才转向那里（每 0.3 秒转 20%）；否则当作没有清晰影子（阴天或散射光），虚拟影子变淡。画面整体亮度决定灯光强弱。
  - 之前的版本只看单帧、没有去渐变、也不要求影子贴着树，顺光拍摄时会把拍摄者的影子和偏暗的近处桌面当成树影，得出几乎相反的方向。用渲染视频复现了这个情况（光在镜头后上方，手和手机的影子落在树前方）：两段这样的视频以及之前两段已知光源的视频，现在都稳定在 5°–13° 以内，被判为“硬光”的读数全部正确，看错的读数都是“软光”，不会移动虚拟太阳；阴天的视频始终判为软光。
- 换算的约定和检测窗口的实际大小是在已知位置的渲染画面上标定的：手机那样的广角，13–25 cm，俯角 30°–70°，横滚最多 15°，树不在画面正中。16 个画面全部跟上，位置误差中位数 1.9 mm（最大 4.8），朝向误差中位数 2.2°（最大 5.7°）。用渲染出来的假摄像头视频跑整页：软件渲染下约 6–8 秒第一次认出树，之后绕着树转也一直跟着。
- 参数：`?debug=1` 把遮挡用的树画成半透明绿色，并显示网络看到的画面和距离、角度、二次校正的成功率、估计的光源方向；`?fov=` 摄像头沿画面长边的视角，默认 63°（手机主摄）；`?nomusic=1` 不放音乐。

## 录像

带 `?rec=1` 打开时，底部中间有一个红色录像按钮（`rec.js`）。按下后歌曲从头开始播放，录到这首歌放完自动停止（93.3 秒，正好是演出的一个完整循环），然后弹出预览，可以“保存视频”，支持的手机上还有“分享”（iOS 可以由此存进相册）。录像途中再按一次可以提前结束。

- 画面就是屏幕上看到的样子，不含按钮和提示：3D 模式录 3D 画面，AR 模式录相机画面加上叠在上面的动画，裁切方式和屏幕一致。录像途中也可以切换 3D / AR。分辨率按屏幕形状，每个 CSS 像素最多 2 个像素，长边最多 1920，30 帧/秒，8 Mbps。
- 声音直接取自歌曲本身（经 Web Audio 接出一路），扬声器照常播放，录进去的不是麦克风。录像期间右上角的音乐按钮不能按，避免暂停后音画对不上。录完歌曲恢复循环播放。
- 格式：浏览器支持时用 MP4（H.264），否则用 WebM。文件名形如 `sakura-qr-20261106-182428.mp4`。
- 自测（无头 Chromium，假摄像头）：3D 录满一首歌得到 93.3 秒的视频，带声音；AR 录像里相机画面和动画都在；`?nomusic=1` 时只有画面，按时钟录 93 秒。

## 部署

`.github/workflows/pages.yml` 在推送到 `main` 时构建并发布 GitHub Pages：执行 `npm ci`，把 import map 用到的几个 three.js 文件按原路径复制进站点，然后部署。第一次需要在仓库的 Settings → Pages 里把 Source 设成 “GitHub Actions”。

`tree.glb` 是示例树，只给演示页用，不属于动画资源。
